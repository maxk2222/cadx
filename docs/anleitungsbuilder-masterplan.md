## 1. Feature definition

User flow (all inside ONE CADX chat):

1. User uploads a PDF instruction manual and zero or more CAD part files
   (`.step/.stp/.stl/.glb/.obj`) into a chat.
2. User says "Erstelle eine AR-Anleitung" (or equivalent). The chat agent starts
   the guide pipeline as a durable job bound to the chat's project.
3. Pipeline extracts ordered assembly steps from the PDF. The LLM receives BOTH
   OCR/page text AND page images (VLM). Each step carries TWO texts:
   - `text` — detailed internal description (drives downstream tools: parts,
     tools, substeps, placement hints);
   - `display_text` — short user-facing AR label shown in the guide.
4. CAD features (ports: cylindrical interfaces with pos/axis/radius/gender) are
   extracted from every uploaded CAD part.
5. Missing CAD parts (required by the manual but not uploaded) are generated by
   the CADX agent itself via the existing `generate_part` codegen pipeline,
   using the PDF steps/figures as the spec.
6. An AssemblyAgent places parts step-by-step using a deterministic placement
   solver; renders are sent back to the VLM for visual verification.
7. A ReviewAgent compares steps+assembly against PDF evidence and writes
   findings; a bounded fix loop re-runs assembly.
8. A `unity_guide.json` (+ rendered step images + CAD models) is emitted and
   attached to the project as downloadable assets.
9. The agent may ask the user clarifying questions at any point (job
   `waiting_for_input` + `answer_questions`), and the user can inject
   additional instruction information via normal chat messages.

Hard requirements (from user):

- "Alles über Agents mit Tooluse" — every extraction/placement decision goes
  through an LLM tool call; deterministic math stays inside tools.
- Resume-safe: killing the worker mid-pipeline must resume at the last
  completed mission (KIARA blackboard semantics).
- Deterministic geometry: transforms come from a solver, never from the LLM.

## 3. Architecture

```
User (chat UI)
  │  uploads PDF + CAD files as Assets; sends "Erstelle AR-Anleitung"
  ▼
POST /chats/{id}/messages ──► arq job run_chat_turn ──► ChatToolSession
                                                          │ tool: start_guide_builder
                                                          ▼
                                        spawn_guide(db, project, pdf_asset, cad_assets)
                                                          │  (new kind="guide" Job; durable payload)
                                                          ▼
                                        worker: agent/guide_runner.py  (durable arq task)
                                                          │  for mission in [doc, steps, parts, assembly, review*, annotate, emit]:
                                                          ▼
        ┌────────────────────────────── GuideState (JSON file, atomic write after every tool) ───┐
        │ document: DocumentIndex │ steps: GuideStep[] │ parts: GuidePart[] │                  │
        │ assembly: AssemblyState │ review: ReviewReport │ missions_done[]   │ output paths    │
        └───────────────────────────────────────────────────────────────────────────────────────┘
              ▲                 │ each mission = ONE bounded LLM tool loop (run_session)
              │                 ▼ scoped GuideToolSession (tools write GuideState, not DB)
        questions? ──► job.waiting_for_input ──► chat surfaces questions ──► answer_questions resumes
```

Key design decisions (DO NOT deviate):

1. **One new job kind** `kind="guide"` on the existing `Job`/`JobStep` model —
   no new queue; runs on the default worker lane like `chat`/`generate`.
   Cancellation, sweeper recovery, SSE progress come free.
2. **GuideState is a file**, not DB rows: `storage.project_dir(pid)/guides/{job_id}/state.json`,
   written atomically (tmp+rename) after every state-changing tool — mirrors
   KIARA `blackboard.save()` and survives worker restarts. Resume = reload file,
   skip `missions_done`.
3. **Missions are sub-agent loops, not one mega-prompt.** Each mission gets its
   own system prompt (in `agent/prompts/guide_*.md` per AGENTS rules), a scoped
   tool allow-list, `max_calls` budget, and a `done_mission` terminator —
   identical to KIARA mission semantics.
4. **Chat stays thin.** The chat agent only calls `start_guide_builder`,
   `guide_status`, and relays questions via the normal
   `waiting_for_input` → `answer_questions` machinery. All heavy work runs in
   the guide job so a chat turn doesn't block for 20+ min.
5. **Deterministic geometry.** LLM picks WHICH ports/parts mate; the solver
   computes the transform. LLM never emits a 4x4 matrix.
6. **Missing parts**: the parts mission compares `required_parts` (from steps)
   against uploaded part names via fuzzy match; each missing part spawns
   `spawn_generate` (sub-job, same project, `part_name` = manual name) and
   blocks; failures surface as a question to the user, not a silent skip.

## 4. Data model (`backend/cadx/guide/state.py`)

Port KIARA `state/models.py` field-for-field where noted; pydantic v2.

```python
class PortInfo(BaseModel):          # KIARA PortInfo
    name: str                        # "port_0", "hole_2"
    pos: list[float]                 # mm, part-local
    axis: list[float]                # unit vector, outward normal of the interface
    radius: float                    # mm
    gender: str                      # "male" | "female" | "flat" | "unknown"
    kind: str = "cylinder"           # cylinder | plane | slot
    depth: float = 0.0               # female ports: usable depth mm

class GuidePart(BaseModel):          # KIARA PartInfo
    id: str                          # slugified part name
    name: str                        # display name from manual / filename
    source: str                      # "uploaded" | "generated" | "library"
    asset_id: str | None = None      # uploaded Asset
    version_id: str | None = None    # generated Version
    mesh_path: str | None = None     # normalized GLB for assembly sim
    step_path: str | None = None
    ports: list[PortInfo] = []
    bbox_min: list[float] = [0,0,0]
    bbox_max: list[float] = [0,0,0]
    mass_hint: str = ""              # "light" | "heavy" for placement order

class GuideSubStep(BaseModel):       # KIARA SubStep
    action: str                      # "place" | "attach" | "orient" | "insert" | "fasten" | "check"
    part: str                        # GuidePart.id or free label
    target: str = ""                 # parent part/step ref
    text: str = ""                   # internal detail
    side: str = ""                   # spatial hint: "left", "top", "from front"

class GuideStep(BaseModel):          # KIARA GuideStepDraft
    number: int
    title: str
    text: str                        # INTERNAL detailed description (drives tools)
    display_text: str                # AR user-facing one/two-liner
    action_type: str = "assembly"    # assembly | check | safety | prep
    required_parts: list[str] = []
    tools: list[str] = []            # physical tools (wrench etc.)
    safety_hint: str = ""
    media_image: str | None = None   # path to PDF figure crop
    source_pages: list[int] = []
    sub_steps: list[GuideSubStep] = []
    parts_delta: list[str] = []      # parts newly placed in this step (for fade-in)

class PageSummary(BaseModel):        # KIARA PageSummary
    page: int
    image_path: str
    text: str
    classification: str = "unknown"  # cover | toc | steps | parts_list | appendix
    figures: list[dict] = []         # [{bbox, image_path, caption}]
    vlm_summary: str = ""

class DocumentIndex(BaseModel):      # KIARA DocumentIndex
    pdf_path: str
    pdf_asset_id: str
    dpi: int = 200
    page_count: int = 0
    language: str = "de"
    doc_type: str = "assembly_manual"
    pages: list[PageSummary] = []
    detected_part_names: list[str] = []

class AssemblyInstance(BaseModel):   # KIARA AssemblyInstance
    part_id: str
    transform: list[list[float]]     # 4x4 row-major, mm
    placed_in_step: int
    substep_idx: int = 0

class AssemblyState(BaseModel):      # KIARA AssemblyState
    instances: list[AssemblyInstance] = []
    joints: list[dict] = []          # [{a_part,a_port,b_part,b_port,residual_mm}]
    step_instances: dict[str, list[str]] = {}   # step number -> part_ids
    status: str = "empty"            # empty | partial | complete

class ReviewFinding(BaseModel):
    severity: str                    # "blocker" | "warning" | "note"
    mission: str                     # which mission must fix it
    step: int | None = None
    text: str
    evidence: str = ""               # page number / render path

class ReviewReport(BaseModel):       # KIARA ReviewReport
    score: float = 0.0               # 0..10
    findings: list[ReviewFinding] = []
    geometry_ok: bool | None = None
    iteration: int = 0

class GuideState(BaseModel):         # KIARA Blackboard
    job_id: str
    project_id: str
    language: str = "de"
    user_notes: list[str] = []       # supplemental info from chat messages
    document: DocumentIndex | None = None
    steps: list[GuideStep] = []
    parts: list[GuidePart] = []
    assembly: AssemblyState = AssemblyState()
    review: ReviewReport = ReviewReport()
    annotations: list[dict] = []     # arrows etc.
    missions_done: list[str] = []
    missions_failed: list[str] = []
    output_dir: str = ""
    unity_guide_path: str | None = None
```

`save()`/`load()` helpers: `tmp`-file + `os.replace`, fsync optional. All tools
mutate `GuideState` then `save()` — never in-memory-only.

```python
MISSIONS = ["doc", "steps", "parts", "assembly", "review", "annotate", "emit"]

async def run_guide_job(ctx: dict, payload: dict) -> dict:
    job = ...            # Job row from ctx["job_id"]
    state = GuideState.load(output_dir) or GuideState(job_id=..., ...)
    for mission in MISSIONS:
        if mission == "review":
            await _review_loop(ctx, state, emit)   # bounded iterations, see §10
            continue
        if mission in state.missions_done:
            continue
        session = build_mission_session(mission, ctx, state)  # scoped tools+prompt

        if mission not in state.missions_done:
            state.missions_failed.append(mission); state.save()
            # decide: fatal for doc/steps; soft for annotate
        state.save()
    return {"ok": mission_failed_empty, "unity_guide": state.unity_guide_path}
```

Progress: `emit("step", {"step": f"guide:{mission}", ...})` at mission
boundaries + after each place_instance (progress = placed/total).

## 8. Mission 3 — `parts` (PartInventory + missing-part generation)

This is the CADX-specific mission — KIARA has no equivalent (it assumes all
parts uploaded). Two halves:

**8a. Feature extraction** (`backend/cadx/guide/cadmeta.py`)

Do NOT port KIARA's 1.9k-line preprocessing router. Implement a slim extractor
that produces the same `PortInfo` shape:

```python
def extract_part_features(part: GuidePart, work_dir: Path) -> GuidePart
    # 1. normalize: STEP → import build123d → BRep + tessellate to GLB;
    #    GLB/STL/OBJ → load via trimesh (bbox + normals only)
    # 2. ports:
    #    STEP path: iterate BRep faces — Cylinder faces → female port
    #    (axis=face axis, pos=axis point at outermost extreme, radius, gender
    #    by convexity sign / hole-vs-boss heuristic from cad/features.py);
    #    planar faces → "flat" ports (pos=centroid, axis=normal) only if face
    #    area ≥ 4% of bbox cross-section (filters noise).
    #    Mesh path: reuse trimesh grouping + cad/features.py hole detection to
    #    find cylindrical bores/bosses → female/male cylinder ports; else fall
    #    back to 6 bbox-face "flat" ports (top/bottom/±x/±y) so placement can
    #    always proceed.
    # 3. write mesh_path (GLB, mm, origin at bbox center-bottom XY like the
    #    part-frame contract) — run through cad/mesh_ops normalize if needed.
```

Where it runs: STEP import needs build123d → must run in the **executor**
(sandbox boundary). Add a tiny executor task or reuse `process_mesh`-style
file-in/file-out call: `runner_entry`-independent helper
`executor_client.run_task("extract_ports", {step_path}) -> {ports,bbox}` —
check `agent/executor_client.py` for the existing call pattern and add ONE new
op rather than a generic exec. Mesh-only files extract in-process (trimesh is a
backend dep already).

**8b. Inventory + generation** (`backend/cadx/guide/part_tools.py`)

Tools for the mission LLM:

- `register_uploaded_part(asset_id, name)` → extract features → `parts[]`.
- `match_required_parts()` → deterministic pass (NOT LLM): normalize names
  (lower, strip suffixes `-_.,()[]`, split camel) from `required_parts` across
  steps vs uploaded names; returns `{matched: {required→part_id}, missing: [...]}`.
  The LLM may then call `alias_part(required_name, part_id)` for fuzzy cases
  (e.g. manual says "Rohr 500" vs file `Pipe_l500.step`).
- `generate_missing_part(required_name, spec_text, reference_pages)` → calls
  `spawn_generate` (mode auto→cad) with a prompt built from the step texts +
  part name; waits for the job (`wait=True` semantics like
  `ChatToolSession._tool_generate_part`); on success registers the Version's
  STEP+GLB via `extract_part_features`, source="generated". On failure →
  `ask_user` (see below) rather than silent skip.
- `ask_user(question)` → sets job `waiting_for_input` + Job.questions; the
  chat UI shows it; resume via `answer_questions`. Reuse
  `spawn.enqueue_resume` plumbing — the guide job's tool writes the question,
  job suspends, chat `answer_questions` resumes it. (Verify the suspend/resume
  protocol used by `orchestrator` questions in `agent/steps/*` — copy that.)
- `list_user_notes()` → surfaces `state.user_notes` (supplemental chat input
  injected between missions).
- `done_mission`.

Seed prompt (`agent/prompts/guide_parts.md`): inventory uploaded assets, match,
resolve missing via generate or `ask_user` if ambiguous (NEVER guess a critical
dimension when the manual doesn't state it — ask).

Acceptance: fixture manual lists ~6 parts; upload 4 CAD files matching names →
mission must match 4, generate or ask for the other 2. Unit-test the name
matcher (`tests/guide/test_part_matching.py`) including the "Rohr 500"↔

## 9. Mission 4 — `assembly` (AssemblyAgent)

Files:

- `backend/cadx/guide/solver.py` — port
  `KIARA:ar_guide_generation_v3/phases/p5_placement/solver.py`. Pure numpy.
  Required API (keep KIARA names):
  ```python
  def solve_attachment(a_part, a_port, b_part, b_port, clearance=0.0) -> list[list[float]]
      # returns 4x4 candidate transforms for part A (moving) so that
      # a_port mates b_port: axis-aligned (180° flip for male/female),
      # pos coincident + clearance along axis; Kabsch for multi-attachment
  def solve_multi_attachment(moving, pairs) -> transform | None
  def solve_free_placement(part, placed, env_hint) -> transform
      # env_hint from step text: "on top of X", "left of Y", "on table"
  def solve_env_placement(part, placed, step_text) -> transform
  ```
  Transforms are mm, CAD Z-up right-handed; conversion to Unity happens only
  at emit.

- `backend/cadx/guide/assembly_scene.py` — trimesh scene manager: load each
  `GuidePart.mesh_path` once, instance per `AssemblyInstance` (transform apply),
  `collisions(instance) -> list[(other, depth_mm)]` (trimesh collision /
  proximity; OBB first, triangle-precise only for suspects),
  `render(view="iso"|step camera) -> Path PNG` — headless: prefer
  `trimesh.scene.save_image` (pyglet); if unavailable in container fall back to
  matplotlib triplot OR the existing executor render path (`renders/mesh.stl`
  pipeline — check `cad/` render helpers and reuse whichever works headless in
  the worker container; add `pyglet`/`pyrender` dep only if needed).

- `backend/cadx/guide/assembly_tools.py` — port `KIARA:tools/cad_tools.py`
  mission subset:
  `list_parts()`, `get_part_features(part_id)` (ports+bbox),
  `find_matching_ports(part_id)` (candidates among placed parts by
  radius/gender/opposing axis, scored — deterministic ranking returned as
  JSON; LLM picks),
  `solve_attachment_preview(moving_part, moving_port, fixed_part, fixed_port)`
  → returns transform + collision report WITHOUT committing,
  `place_instance(part_id, transform, step, substep)` → append instance +
  joints + `step_instances` → save state,
  `rotate_instance(part_id, euler_deg)` (re-solve preferred, this is escape
  hatch),
  `render_assembly(view?, highlight_part?) -> attaches PNG to next LLM msg`,
  `check_collisions() -> report`,
  `validate_assembly_geometry()` (deterministic: all joints residual < 1mm,
  no collision > 0.5mm depth, all required parts placed),
  `validate_assembly_completeness()` (every `required_parts` placed exactly
  once, in ascending step order),
  `reset_step(step)` (remove instances placed by step — for fix loop),
  `done_mission`.

- `backend/cadx/agent/prompts/guide_assembly.md` — port AssemblyAgent prompt:
  ownership = `parts`+`assembly` only; workflow per step: read step text →
  identify new parts → for each: `find_matching_ports` → `solve_*_preview` →
  `render_assembly` → verify against `media_image`/PDF figure → `place_instance`
  → final `check_collisions` + `validate_*`. Solver output is a CANDIDATE —

## 10. Mission 5 — `review` (ReviewAgent + fix loop)

- `backend/cadx/guide/review_tools.py` — port `KIARA:agents/review_agent.py`
  tool set. READ-ONLY except: `write_review_report(score, findings)`,
  `append_plan(text)` (scratchpad file `plan.md` in output dir — port
  `KIARA:tools/plan_tools.py` read/append/write/delete; shared across missions
  so AssemblyAgent can read findings next iteration).
- Orchestrator-side loop (in `guide_runner.py`, NOT in the LLM):
  ```python
  for it in range(REVIEW_MAX_ITERS):          # default 3, runtime setting
      run_mission("review")                    # writes state.review
      if state.review.score >= REVIEW_PASS:    # default 8.0
          break
      blockers = [f for f in findings if severity=="blocker"]
      if not blockers and it >= 1: break       # no fixable findings
      rerun_steps = sorted({f.step for f in blockers if f.step})
      reset those step instances; state.assembly.status="partial"
      run_mission("assembly")                  # targeted re-assembly
  ```
  Stuck detection (port from KIARA orchestrator): if the same finding texts
  recur verbatim after a fix pass → break, mark `missions_failed`.
- `agent/prompts/guide_review.md` — port ReviewAgent prompt: read-only
  verifier; compare each step's assembly state + renders vs `source_pages`
  figures; score 0..10 rubric (port rubric from KIARA prompt); findings must
  cite evidence; NEVER edit state directly.

Acceptance: `tests/guide/test_review_loop.py` — fake missions stubbed; loop
stops at threshold, reruns on blocker, bails on identical findings.

## 17. Known pitfalls (port these fixes deliberately)

From KIARA analysis and CADX conventions:

- Page images must reach the LLM as IMAGE ATTACHMENTS (base64/bytes in the
  vision message slot), never as file paths in text and never base64 inside
  tool JSON — KIARA does this via separate image slots; CADX `run_session`
  already supports image attach via session results (`_images` mechanism in
  `ChatToolSession` — reuse it: tools return `{"images": [path]}`).
- Keep tool results small: `list_figures`/`get_all_page_text` must truncate
  (cap ~2k chars/page, note truncation) or the context explodes on 50-page
  manuals. KIARA's loop has token-based compaction; CADX has
  `agent_context_budget_frac` compaction — keep results small anyway.
- `display_text` vs `text` MUST be separate required fields — merging them
  reintroduces the KIARA v3 bug where AR showed internal notes.
- Never let `place_instance` accept a raw LLM matrix without a prior
  `solve_*_preview` in the same turn — the tool enforces this by requiring a
  `candidate_id` returned by the preview call (id + in-memory cache), NOT a
  matrix argument. (Deviates slightly from KIARA where the LLM sees the
  matrix — our contract is stricter on purpose.)
- mm→m + RH→LH conversion is the #1 silent-corruption risk: golden-test it
  with a known transform, and never convert anywhere except `unity.py`.
- Missing-part generation can loop forever: cap `guide_gen_missing_max` and
  require `ask_user` after the cap.
- The fixture PDF is German — prompts must be bilingual-tolerant; steps keep
  the manual's language for `display_text`, internal `text` may be English.
